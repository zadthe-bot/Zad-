# Customer App — Setup

This folder has the app's Dart source (`lib/`), `pubspec.yaml`, and the CI workflow.
It does **not** yet have the native `android/`, `ios/`, `web/` folders — those are
generated by the Flutter CLI on your machine, then these files sit on top.

## 1. Generate the native scaffold
From inside `Customer/`:
```bash
flutter create --org com.yourcompany --project-name customer .
```
This adds `android/`, `ios/`, `web/`, and a few other files around the `lib/` you already have. Say yes if it asks to overwrite `pubspec.yaml` — actually don't; if prompted, choose **no** so your dependencies aren't wiped, then re-check `pubspec.yaml` has the packages listed below.

```bash
flutter pub get
```

## 2. Connect Firebase
```bash
dart pub global activate flutterfire_cli
flutterfire configure
```
Pick (or create) your Firebase project, select Android + iOS + Web. This overwrites the placeholder `lib/firebase_options.dart` with real config and drops the native config files (`google-services.json`, `GoogleService-Info.plist`) into `android/app/` and `ios/Runner/`.

In the Firebase console, turn on:
- **Authentication** → Sign-in method → **Email/Password**
- **Firestore Database** → Create database (test mode to start; lock down with rules before real users — see the Firestore schema doc below)

## 3. Run it
```bash
flutter run
```

## 4. Set up release signing (needed for the AAB / Play Store)
Generate a keystore once, locally:
```bash
keytool -genkey -v -keystore release.keystore -alias customer -keyalg RSA -keysize 2048 -validity 10000
```
Keep `release.keystore` **out of git** (add it to `.gitignore` — `flutter create` already ignores `android/key.properties` by default, add `*.keystore` too).

In `android/app/build.gradle`, inside `android { ... }`, add signing config that reads from `key.properties`:
```gradle
def keystoreProperties = new Properties()
def keystorePropertiesFile = rootProject.file('key.properties')
if (keystorePropertiesFile.exists()) {
    keystoreProperties.load(new FileInputStream(keystorePropertiesFile))
}

android {
    ...
    signingConfigs {
        release {
            keyAlias keystoreProperties['keyAlias']
            keyPassword keystoreProperties['keyPassword']
            storeFile keystoreProperties['storeFile'] ? file(keystoreProperties['storeFile']) : null
            storePassword keystoreProperties['storePassword']
        }
    }
    buildTypes {
        release {
            signingConfig signingConfigs.release
        }
    }
}
```

## 5. Add GitHub Secrets (for the CI build)
Repo → Settings → Secrets and variables → Actions → New repository secret:

| Secret name | Value |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | `base64 -i release.keystore \| pbcopy` (Mac) or `base64 -w0 release.keystore` (Linux) — paste the output |
| `ANDROID_KEYSTORE_PASSWORD` | the store password you set with `keytool` |
| `ANDROID_KEY_ALIAS` | `customer` (or whatever alias you used) |
| `ANDROID_KEY_PASSWORD` | the key password you set with `keytool` |

Push to `main` (touching anything under `Customer/`) and the workflow in `.github/workflows/build.yml` builds a signed `app-release.apk` and `app-release.aab`, downloadable from the Actions run's Artifacts.

## Firestore schema (shared with the Restaurant app later)

**`restaurants/{id}`**
```
name: "Luigi's Pizza"
cuisine: "Italian"
isOpen: true
rating: 4.6
etaMinutes: 25
imageUrl: ""
```

**`restaurants/{id}/menu/{itemId}`**
```
name: "Margherita Pizza"
description: "Tomato, mozzarella, basil"
price: 12.99
```

**`orders/{id}`** — created by this app on checkout:
```
customerId, customerName, restaurantId, restaurantName,
items: [{id, name, price, qty}],
total, address,
status: "placed" | "preparing" | "on_the_way" | "delivered",
createdAt
```
The order tracking screen listens live — when the Restaurant app updates `status`, it appears instantly here.

## What's built
- Email/password auth (Riverpod-managed auth state, redirect-guarded routes via go_router)
- Live restaurant list, menu, cart (single-restaurant cart with a switch-confirmation prompt)
- Checkout → writes to Firestore
- Live order tracking with the heat-gauge status bar
- Order history, basic profile/logout
- CI workflow producing signed APK + AAB on every push to `main`
